# IoT and electronics hardware makers

## Who buys

Small hardware companies and solo founders (1–20 people) selling sensors, dev boards, gateways, modules and smart devices. Usually engineering-led: strong product, weak marketing. Decision maker: founder or CTO. Global, outreach in English.

The studio's edge here is technical: we read the datasheet and schematic-level claims correctly, so the creative never says something an engineer buyer would laugh at.

## What they lack (typical `weakness_noted`)

- Product photos of a bare PCB on a desk; no context of the product in use.
- No explainer of what problem it solves in 15 seconds.
- Crowdfunding page with a long founder video and no short cut-downs for ads.
- Docs and specs strong, landing page weak.

## Angle bank (verify each against real buyer language in research)

- Time to first result: "flash, connect, see data in N minutes" — only if the docs show it.
- Integration: works with Home Assistant, ESPHome, MQTT, Arduino, Raspberry Pi — only listed integrations.
- Battery life and range — only with the test conditions stated in the datasheet.
- Open source / hackability, documentation quality, community.
- Replacing a messy DIY setup (breadboard, cables, unreliable modules).
- Use-case scenes: greenhouse, home energy monitoring, cold-chain, workshop.

## Research sources

Their docs, GitHub repo issues and README, Tindie/Crowd Supply listing and comments, Hackaday and Hackster write-ups, relevant subreddits (r/homeassistant, r/esp32, r/embedded, r/IOT), competitor products' ads and landing pages.

## Prospect sources

Tindie and Crowd Supply sellers, hardware projects on Kickstarter/Indiegogo (live and recently funded), Hackster product pages, EU hardware startup lists, exhibitors at embedded/IoT trade shows.

## Deliverables and shot list

Product in its real environment (enclosure on a wall, sensor in soil, gateway on a shelf); exploded or callout view of key components drawn from the actual board photo; screen recording of the dashboard or app with real data; size reference (coin, hand); setup sequence in 3 steps.

## QA additions (on top of studio-core stage 6)

- Every spec (MCU, radio, frequency band, range, power draw, battery life, IP rating, operating temperature) matches the datasheet and keeps its test conditions.
- Certifications (CE, RED, FCC, UKCA, RoHS) appear only if the client has them; never implied by a logo.
- Generated or edited board images keep the real component layout, connectors and silkscreen — do not let a model invent chips or ports.
- "Secure", "encrypted", "GDPR compliant" only with the client's written basis.
- Code or terminal text shown on screen is real and correct.
